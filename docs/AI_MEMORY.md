## 4b. Universal Logo — Technique & Usage Rules

| Key | Value |
|-----|-------|
| **file name** | `universal_logo.svg` (SVG vector) and `universal_logo.png` (3840×3840 transparent PNG) — both in project root |
| **purpose** | Single logo file that reads clearly on ANY background: dark, light, coloured, or mid-tone |
| **technique** | White fill on "Geeves." wordmark + `paint-order: stroke fill` with a 3pt black stroke at 78% opacity drawn BEHIND the fill + `feDropShadow` (stdDeviation=8, opacity=0.65) as outer soft halo. On dark backgrounds the black stroke blends in and white fill reads cleanly. On white/light backgrounds the black stroke outline creates contrast and the shadow adds depth. |
| **why not feDropShadow alone** | `feDropShadow` on white text against white background has insufficient contrast — the shadow blurs outward but the white fill covers the centre. The stroke+paint-order technique is the industry-standard solution. |
| **why not two text passes** | Duplicate text elements misalign due to font metric differences between renderers (cairosvg vs browser). Single element with paint-order is renderer-safe. |
| **"Life" treatment** | Brand teal #2AAFA9 fill only — saturated enough to read on any surface. Light feDropShadow (stdDeviation=5, opacity=0.40) for depth only. No stroke needed. |
| **tagline treatment** | Mid-grey #9CA3AF fill + light feDropShadow (stdDeviation=4, opacity=0.35). Readable on dark, subtle on light. |
| **where to use** | Login page, DashboardLayout auth gate, Google OAuth consent screen branding, app store icons, any surface where background is unknown or variable |
| **where NOT to use** | Inside the app dashboard sidebar (use theme-aware GeevesLogo.tsx there — dark bg is guaranteed) |
| **favicon** | Constellation mark only (no wordmark) rendered at 32×32 and 180×180 as ICO/PNG. See client/public/favicon.ico and client/public/apple-touch-icon.png |
| **stroke width history** | Started at 16pt (too heavy), reduced to 8pt (still heavy), settled at 3pt (subtle outline, correct balance) |
| **renderer note** | cairosvg does NOT support `paint-order` or `feDropShadow` on text — always verify in headless Chromium (Puppeteer). The SVG renders correctly in all browsers. |

| **users vs household members** | Two separate identity layers exist:  **users** (platform OAuth identity): - Created when a person completes Google OAuth for the first time - Contains: id, email, name, googleId, role (admin/user/system_admin), deviceTimezone, deviceCity - May NOT exist for invited-but-not-yet-joined members (they have a household_members row but no users row) - householdId and memberId are stamped on users after they claim their invite or create a household  **household_members** (constellation role record): - Created immediately when an admin sends an invite (status=invited) - Always exists once a member is invited, even before they log in - Contains: id, householdId, userId (nullable until claimed), role, status, name, email, pronouns, relationship, interfaceMode, geevesAccess - userId is null until the member claims their invite via Google OAuth  **Key invariant**: A member can have a household_members row with userId=null (invited, not yet joined). A user can have householdId=null if they signed up via OAuth but haven't joined/created a household yet.  **Join pattern**: Always join via household_members.userId = users.id, not via users.householdId directly. |
